工作原理

      
每次按键，页面都会根据你填写的六个字段重新构建整个标签块。每个值都会先去除首尾空格，再经过转义处理，把特殊字符转换为 HTML 实体。只有你实际填写的字段才会生成对应标签，一些决策已经替你做好：图片网址留空时，twitter:card 会从 summary_large_image 降级为 summary，因为大图卡片没有图片就没有意义。字数统计对标题按 60 字符、对描述按 160 字符检查，请把它们当作参考而非硬性规则：Google 是按像素宽度而不是字符数来截断摘要的。

      
大多数标签生成器都不会告诉你的一点：meta description 并不是排名因素，Google 多年来一直这么说。它真正影响的是点击率，因为它通常就是搜索结果中你的链接下方展示的文案。即便如此，当你的描述与搜索意图不匹配时，Google 有一半以上的概率会重写它。用人类能理解的语言来写，控制在 160 字符以内，不必过度纠结。对于社交分享图，1200×630 是安全选择，与 Facebook 推荐的 Open Graph 尺寸一致。

      
一切都在本页面自己的 JavaScript 中完成：标签字符串在本地组装，除非你点击复制用到剪贴板，否则完全不会涉及网络。打开开发者工具，查看网络面板，在每个字段中输入内容：你的标题、网址和账号信息永远不会离开浏览器。

    




    
常见问题

    

      

        为什么标题建议控制在 60 个字符以内？
        
Google 通常会在大约 60 个字符处截断搜索结果标题（实际以像素宽度为准，并非严格的字符数限制）。控制在这个长度以内，可以让完整标题显示在搜索结果中，而不会被省略号截断。

      

      

        我需要同时添加 Open Graph 和 Twitter 标签吗？
        
如果没有 twitter:card 专用标签，Twitter/X 实际上会自动回退使用 Open Graph 标签。但同时明确添加两者能让你有更多控制权，也能更好地兼容 LinkedIn、Slack 等同样读取 Open Graph 标签的平台。

      

      

        这些内容会被发送到别的地方吗？
        
不会。标签根据你输入的内容完全在浏览器中生成，不会上传任何内容。
