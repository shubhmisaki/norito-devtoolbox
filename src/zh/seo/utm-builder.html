工作原理

      
基础网址通过浏览器自带的 URL API 解析，这也是为什么在你输入 https:// 之前会报错：解析器需要一个协议，而这正是你的浏览器用于真实导航的同一个解析器，所以如果这里能接受这个网址，这个网址就能正常使用。五个 utm_ 值分别通过 searchParams.set() 应用，它会自动对特殊字符进行百分号编码。使用 set() 而不是字符串拼接，还意味着网址上已有的查询参数会被保留，清空某个字段会移除对应参数而不是留下一个空的 utm_term=。

      
一个会悄悄毁掉活动报表的错误：UTM 值在分析工具中区分大小写。GA4 会把 email、Email 和 EMAIL 当作三个不同的来源，把一个活动的数字拆成三份。请始终使用全小写，绝不偏离。同时也要让 utm_medium 保持在 GA4 默认渠道分组能识别的词汇范围内，比如 email、cpc、social 或 referral；如果自创一个词，你的流量就会落入没人查看的“未分配”分类。

      
网址会随每次按键在本地实时组装，本页面从不请求、发送或记录它。打开开发者工具的网络面板并随意输入：不会触发任何请求。生成好的链接只有在你把它粘贴到实际投放渠道时才会真正被访问。

    





    
常见问题

    

      

        source 和 medium 有什么区别？
        
source（来源）指流量来自哪里（比如 google、newsletter、twitter）。medium（媒介）指渠道类型（比如 cpc、email、social、organic）。两者结合起来回答的是“这次访问从哪里来、通过什么方式来”。

      

      

        我需要填写 term 和 content 吗？
        
只有在需要更细致的跟踪时才需要。term 通常用于付费搜索关键词，content 用于区分指向同一位置的两个不同链接（例如同一封邮件里的两个按钮）。

      

      

        这适用于任何分析工具吗？
        
适用。utm_source/medium/campaign/term/content 是事实上的标准格式，Google Analytics 和大多数其他分析平台都能读取，并不是 Google 专有的格式。
