工作原理

验证通过 JSON.parse 完成，这正是浏览器和 Node.js 在运行时使用的原生解析器，因此凡是能通过这里的内容，在生产环境中也一定能正确解析，而不是某种近似语法的模拟。解析失败时，引擎要么直接返回行号和列号，要么只返回一个原始字符位置；对于后一种情况，工具会把输入截取到该位置，并通过统计换行符数量换算出错误框中显示的行号与列号。

树形视图通过递归遍历解析后的值构建为可折叠节点；任何超过 300 项的对象或数组只会在视图中被截断，绝不会影响复制或下载的实际输出，因此几兆字节的 API 响应依然可以顺畅滚动查看。经过引擎处理还有一个值得了解的副作用：数字会以 JavaScript 的 64 位浮点数重新序列化。外观上的写法会被规范化（1e2 变成 100，0.50 变成 0.5），而超过 2 的 53 次方的整数，比如 19 位的数据库或 Twitter 风格ID，可能会悄悄丢失末尾几位数字。如果你的 JSON 里包含这类超大 ID，请在格式化前把它们保留为字符串。

解析、格式化和压缩都会在你每次按键时于本页面的 JavaScript 中完成。打开开发者工具的"网络"面板，粘贴一段真实的 API 响应即可亲自验证：没有任何请求离开你的浏览器，这也是为什么粘贴包含令牌或客户数据的内容在这里是安全的。
